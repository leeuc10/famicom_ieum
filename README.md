# FAMI FIGHTERS

Raspberry Pi를 본체로, ESP32-S3 두 대를 1P/2P 컨트롤러로 쓰는 **페미컴풍 2D 대전 격투 게임기**입니다. 복잡한 조작이나 긴 학습 없이 두 명이 바로 대결하는 로컬 멀티플레이 경험을 목표로 합니다.

> 문서 버전 v0.2 · 갱신 2026-08-23 · 상태: 플레이어블 프로토타입 + 조작기 펌웨어 확정(실기 검증 대기)

이 프로젝트는 에뮬레이터나 상용 게임 ROM을 포함하지 않습니다. 직접 만든 게임을 실행하는 콘솔의 출발점입니다.

## 기획

### 배경

- 레트로 게임기의 직관적인 재미와 직접 제작한 하드웨어의 소장성을 결합합니다.
- 범용 PC 게임은 설치·로그인·복잡한 메뉴 때문에 짧은 대전을 시작하기 어렵습니다.
- Raspberry Pi와 ESP32를 쓰면 화면·입력 장치·케이스를 비교적 낮은 비용으로 모두 직접 설계할 수 있습니다.

핵심은 **전원을 켜고, 컨트롤러를 잡고, 즉시 둘이 대결하는 경험**입니다.

### 목표

1. 2명이 한 화면에서 1~3분 안에 한 판을 끝낼 수 있는 대전 격투 게임을 만듭니다.
2. 페미컴을 연상시키는 단순한 색상, 픽셀형 도형, 명확한 HUD를 구현합니다.
3. Raspberry Pi에서 안정적으로 60 FPS에 가깝게 실행합니다.
4. ESP32 기반 1P·2P 전용 컨트롤러를 연결할 수 있는 입력 구조를 갖춥니다.

**비목표** — 상용 ROM 실행/에뮬레이터, 온라인 대전 및 계정, 3D 그래픽, 초기 단계의 다수 캐릭터·스토리 모드.

### 타깃 사용자

| 사용자 | 상황 | 기대 경험 |
| --- | --- | --- |
| 학생·친구 그룹 | 쉬는 시간 또는 모임 | 설명 없이 바로 시작하는 짧은 대전 |
| 레트로 게임 팬 | 전시·개인 제작물 체험 | 페미컴 감성과 커스텀 하드웨어의 결합 |
| 메이커 프로젝트 관람자 | 시연 또는 발표 | 소프트웨어와 물리 컨트롤러가 함께 동작하는 결과물 |

### 핵심 사용자 흐름

```text
부팅 → 타이틀 화면 → Start 입력 → 대전 진행 → 라운드 결과
     → 2선승 매치 종료 → 재대전 또는 타이틀 복귀
```

## 게임 설계

### 기본 규칙

| 항목 | 내용 |
| --- | --- |
| 플레이 인원 | 로컬 2인 |
| 승리 조건 | 2선승제 |
| 라운드 시간 | 60초 |
| 시간 종료 | 잔여 체력이 높은 플레이어 승리, 동률이면 무승부 |
| 동시 KO | 무승부 |
| 화면 해상도 | 800 × 480 디스플레이 지원 (내부 960 × 540, 비율 유지 축소) |
| 목표 프레임 | 60 FPS |

### 전투 시스템

공격은 **발동(startup) → 판정(active) → 경직(recovery)** 세 구간으로 나뉩니다. 판정 구간에만 상대를 맞힐 수 있고, 그 구간에만 히트박스가 화면에 표시됩니다.

| 공격 | 발동 | 판정 | 경직 | 피격 경직 | 이득 | 피해 | 사거리 | 넉백 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 펀치 (A) | 3F | 4F | 8F | 11F | **+0F** | 8 | 44px | 24px |
| 킥 (B) | 6F | 5F | 10F | 16F | **+2F** | 13 | 62px | 40px |

- **이득 프레임 = 피격 경직 − (명중 후 남은 판정 + 경직).** 명중이 판정 첫 프레임에 나기 때문에 남은 판정 프레임도 때린 쪽의 구속 시간에 들어갑니다.
- 이득이 각자의 발동 프레임(3F, 6F)보다 작으므로 **맞은 쪽이 항상 되받아칠 수 있습니다.** 연타 우위가 성립하지 않습니다. 가드를 넣기 전까지는 때린 쪽에 이득을 더 주지 않는 편이 낫습니다.
- 값은 `main.py` 의 `ATTACKS` 표 한 곳에서 조정합니다.

그 밖의 규칙:

- **피격** — 체력 감소, 넉백, 피격 경직(이동·점프·공격 불가), 짧은 피격 플래시. 맞으면 진행 중이던 자기 공격이 끊깁니다.
- **동시 타격** — 양쪽 판정을 먼저 모두 확정한 뒤 피해를 적용합니다. 순서대로 처리하면 먼저 도는 쪽이 상대 공격을 끊어 항상 P1이 유리해집니다.
- **몸통 충돌** — 지상에서는 두 캐릭터가 겹치지 않도록 밀어냅니다. 공중에서는 통과해 상대를 뛰어넘을 수 있습니다. 한쪽이 벽에 막히면 남은 몫만큼 반대쪽이 더 밀려납니다.
- **방향** — 공격 중에는 방향이 잠깁니다. 상대가 머리 위를 넘어갈 때 판정 박스가 등 뒤로 순간이동하는 것을 막습니다.
- **이동 제한** — 스테이지 가장자리 밖으로 나갈 수 없습니다.
- **상태 표시** — 플레이어별 체력 바, 라운드 점수, 남은 시간, 현재 라운드.

### 화면 구성

| 화면 | 목적 | 주요 요소 |
| --- | --- | --- |
| 타이틀 | 대전 시작과 조작 안내 | 로고, 시작 안내, 1P·2P 조작법, 종료 안내 |
| 대전 | 실시간 게임 플레이 | 스테이지, 캐릭터, 체력 바, 타이머, 라운드 표시 |
| 일시정지 | 게임 중단 및 재개 안내 | 반투명 오버레이, 재개 안내 |
| 라운드 결과 | 다음 라운드 전 승패 전달 | `1P/2P 라운드 획득` 또는 `무승부` |
| 매치 결과 | 최종 승자 확인 및 재시작 | 승자 문구, 재대전·타이틀 안내 |

### 비주얼 및 사운드 방향

- 제한된 고채도 팔레트(빨강, 파랑, 금색, 하늘색)를 씁니다.
- 캐릭터는 외부 에셋 없이도 보이는 픽셀형 도형 스타일입니다.
- 텍스트와 체력 바는 멀리서도 읽을 수 있는 큰 대비를 유지합니다.
- 추후 캐릭터 스프라이트, 스테이지 배경, 타격 이펙트를 추가합니다.
- 사운드는 타이틀 BGM, 공격·피격 효과음, 라운드 시작·승리 효과음 순으로 추가합니다. **사운드 파일이 없어도 실행 가능해야 합니다.**

## 조작

컨트롤러 한 대는 **조이스틱 1개(4방향) + A + B + Start + Select = 8입력**입니다. 페미컴 원본 패드와 같은 구성입니다.

게임은 물리 장치를 직접 보지 않고 `input_adapter.py` 가 정규화한 **논리 버튼 8개**만 봅니다. ESP32 조작기는 USB HID 키보드로 인식되며 아래 표와 **똑같은 키를 보냅니다.** 따라서 키보드와 조작기를 동시에 꽂아도 둘 다 동작하고, 조작기가 없어도 개발할 수 있습니다.

| 논리 버튼 | 역할 | 1P 키보드 | 2P 키보드 | GPIO |
| --- | --- | --- | --- | --- |
| `up` | 점프 | `W` | `↑` | 4 |
| `down` | 예약 (향후 가드/앉기) | `S` | `↓` | 5 |
| `left` / `right` | 이동 | `A` / `D` | `←` / `→` | 6 / 7 |
| `punch` | 펀치 (A 버튼) | `F` | `,` | 15 |
| `kick` | 킥 (B 버튼) | `G` | `.` | 16 |
| `start` | 대전 시작 / 일시정지 | `Enter` `Space` `P` | `F2` | 17 |
| `select` | 타이틀 복귀 | `Esc` | `F3` | 18 |

화면별 동작:

| 화면 | 입력 | 동작 |
| --- | --- | --- |
| 타이틀 | `Start` 또는 아무 A/B | 대전 시작 |
| 대전 | 조이스틱 좌/우 · 위 | 이동 · 점프 |
| 대전 | A / B | 펀치 / 킥 |
| 대전 | `Start` | 일시정지 / 계속 (결과 표시 중에는 무시) |
| 모든 화면 | `Select` | 타이틀로 돌아가기 |
| 매치 종료 | `Start` 또는 아무 A/B | 새 대전 시작 |
| 모든 화면 | `Start` + `Select` 동시 | 게임 종료 |

- 타이틀·매치 종료에서 **아무 A/B 버튼**으로도 시작됩니다. Start를 못 찾는 사람이 많기 때문입니다.
- `Start` + `Select` 를 종료로 둔 이유는 부팅 자동 실행 상태에서 키보드 없이 빠져나갈 유일한 수단이기 때문입니다. 단독 버튼으로 두면 전시 중 관람객이 실수로 누릅니다.

## 빠른 실행 (macOS / Linux / Raspberry Pi OS)

### 1. 필요한 것

- Python 3.10 이상 (`python3 --version`으로 확인)
- `pip`
- 키보드와 디스플레이
- **한글 폰트** — 화면 문구가 한국어입니다. Raspberry Pi OS에는 기본으로 없을 수 있습니다.

  ```bash
  sudo apt install -y fonts-nanum
  ```

Raspberry Pi OS Desktop에는 화면 환경이 갖춰져 있어 가장 간단합니다. Lite 이미지는 별도의 Wayland/X11 또는 프레임버퍼 설정이 필요하므로 처음에는 Desktop 이미지를 권장합니다.

#### 폰트가 결정되는 방식

`fonts.py` 가 아래 순서로 찾고, **한글이 실제로 그려지는지 렌더 결과까지 확인**한 뒤 고릅니다. 폰트 이름만 맞고 글리프가 없는 폰트는 조용히 빈 네모를 그리기 때문입니다.

1. `assets/fonts/` 안의 `.ttf` / `.otf` / `.ttc` — 직접 넣은 것이 최우선
2. 시스템 폰트 — `nanumgothic` → `notosanscjkkr` → `applesdgothicneo` → …
3. 못 찾으면 **자동으로 영문 문구로 실행**되고 시작할 때 설치 안내를 출력합니다

`assets/fonts/` 는 비워 두어도 됩니다. 페미컴 느낌을 살리려면 갈무리 같은 한글 픽셀 폰트(OFL)를 넣는 것을 권합니다. 외부 폰트를 넣을 때는 라이선스를 아래 [라이선스](#라이선스) 절에 함께 기록하세요.

### 2. 프로젝트 받기

```bash
git clone <저장소-주소> fami-prototype
cd fami-prototype
```

압축 파일을 받았다면 압축을 풀고 해당 폴더로 이동합니다.

### 3. 가상환경과 의존성 설치

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install --upgrade pip
python3 -m pip install -r requirements.txt
```

Windows PowerShell에서는 활성화 명령만 바꿉니다.

```powershell
.venv\Scripts\Activate.ps1
```

### 4. 실행

```bash
python3 launcher.py
```

800×480 디스플레이에서는 `python3 launcher.py`만 실행하면 자동으로 전체 화면으로 열립니다. 통합 메뉴와 패들 게임은 800×480 화면을 사용합니다. 격투 게임은 기존 비율을 유지해 800×450으로 표시하고 위아래에 15px씩 여백을 둡니다. TV 아래에 놓고 컨트롤러로 사용하는 콘솔을 기준으로 모든 해상도에서 전체 화면이 기본입니다. TV 해상도에 맞춰 비율을 유지해 표시하며, 개발할 때는 `--windowed`로 창 모드를 사용할 수 있습니다.

전체 화면을 직접 지정하려면:

```bash
python3 launcher.py --fullscreen
```

가장자리가 계속 조금 잘리면 각 가장자리에 5% 여백을 두고 실행하세요:

```bash
python3 launcher.py --fullscreen --margin 5
```

`--margin`은 0~20 사이 정수입니다. 바탕화면도 잘린다면 게임 밖의 디스플레이 설정을 별도로 확인해야 합니다.

### 통합 게임 메뉴

기본 실행 파일은 `launcher.py`입니다. USB 조작기 또는 키보드로 게임 선택부터 복귀까지 조작할 수 있습니다.

| 화면 | 조작 |
| --- | --- |
| 통합 메뉴 | 방향키: 선택, A / START: 게임 실행 |
| 통합 메뉴 종료 | SELECT → A / START로 확인, B / SELECT로 취소 |
| 게임 중 | START + SELECT: 게임 종료 후 통합 메뉴 복귀 |
| 패들 듀얼 | 1P W/S, 2P ↑/↓ 또는 조이스틱 위/아래. 먼저 7점 획득 시 승리 |
| 패들 듀얼 일시정지 | START, A / START로 계속 |

현재 **파미 파이터즈(격투)**와 **패들 듀얼(탁구)** 두 게임이 들어 있습니다. 메뉴 종료는 앱 종료이며 Raspberry Pi의 전원을 끄지 않습니다. 게임 오류가 발생하면 메뉴로 돌아오고 오류 안내를 표시합니다. 실행·복귀 때 누르고 있던 버튼은 놓은 뒤 다시 눌러야 합니다.

격투 게임만 직접 실행하려면 `python3 main.py`를 사용합니다.

#### 게임 추가

`games.json` 목록에 항목을 추가하고 런처를 다시 실행하세요. 목록이 길어지면 3개씩 페이지가 바뀝니다.

```json
{
  "title": "MY GAME",
  "title_ko": "새 게임",
  "description": "A short description",
  "description_ko": "간단한 게임 설명",
  "players": "1-2 PLAYERS",
  "script": "my_game.py"
}
```

`script`는 런처 폴더 기준 Python 파일 경로입니다. 게임에는 같은 Python 환경으로 `--fullscreen` 또는 `--windowed`, `--margin 0~20`이 전달되므로 이 옵션을 처리해야 합니다. `console_ui.py`의 `options()`와 `ConsoleDisplay`를 재사용하면 화면·조작기 입력을 공유할 수 있습니다. 게임 프로세스가 종료되면 런처가 다시 열립니다. 다른 게임을 추가할 때도 START + SELECT 종료 처리를 넣으세요. ROM 에뮬레이터 자동 실행 기능은 포함하지 않습니다.

## Raspberry Pi에서 실행하기

### 권장 본체

- **Raspberry Pi 4 Model B 또는 Pi 5** — 1080p 출력 및 향후 메뉴/사운드 확장에 여유가 있습니다.
- Raspberry Pi 3 Model B+ — 이 프로토타입은 가능하지만 향후 무거운 UI에는 제한이 있을 수 있습니다.
- 안정적인 5V 전원 어댑터와 방열 대책을 사용하세요.

### 시스템 구성

```text
ESP32-S3 조작기 1P ─┐
                     ├─ USB HID ─ Raspberry Pi ─ HDMI ─ TV/모니터
ESP32-S3 조작기 2P ─┘                  │
                                       └─ Python/Pygame 게임
```

| 구성 요소 | 역할 | 확정안 |
| --- | --- | --- |
| 본체 | 게임 실행·화면 출력 | Raspberry Pi 4 Model B 또는 Pi 5 |
| 컨트롤러 | 1P·2P 입력 | ESP32-S3 2대, 8버튼 |
| 통신 | 컨트롤러 입력 전송 | **USB HID 키보드** (유선) |
| 디스플레이 | 게임 화면 출력 | HDMI 입력 TV 또는 모니터 |
| 전원·케이스 | 안정성·완성도 | 정격 5V 전원, 방열, 전용 케이스 |

USB HID는 파이에서 일반 키보드로 인식되어 구현 난도와 지연 관리 측면에서 유리하고, 페어링·배터리 문제가 없어 전시에 안전합니다. Bluetooth HID는 재연결 처리가 필요하므로 채택하지 않았습니다.

### 디스플레이 연결

- Raspberry Pi 4/5의 기본 외부 영상 출력은 **micro-HDMI** 입니다. micro-HDMI → HDMI 케이블/어댑터로 연결합니다.
- 일반적인 Raspberry Pi B 보드에는 DisplayPort 포트가 없습니다. DP 모니터를 쓴다면 **능동형 HDMI → DisplayPort 어댑터**가 필요할 수 있습니다. 케이블 방향(HDMI source → DP display)을 반드시 확인하세요.
- 전원을 넣은 뒤 바탕화면이 모니터에 보이는지 먼저 확인하고 게임을 실행합니다.

## ESP32 조작기 만들기

조작기 2대는 **ESP32-S3** 를 쓰고 **USB HID 키보드**로 동작합니다.

### 배선 (조작기 1대 기준)

간단한 핀맵입니다. **ESP32-S3의 GPIO 번호**이며 보드의 물리 핀 순서나 Raspberry Pi 핀 번호가 아닙니다. 1P·2P 모두 같은 배선입니다.

```text
ESP32-S3                     스위치                  공통선
GPIO4  ──────────────────── [위 ↑] ──────────────────┐
GPIO5  ──────────────────── [아래 ↓] ────────────────┤
GPIO6  ──────────────────── [왼쪽 ←] ────────────────┤
GPIO7  ──────────────────── [오른쪽 →] ──────────────┤
GPIO15 ──────────────────── [A / 펀치] ──────────────┤
GPIO16 ──────────────────── [B / 킥] ────────────────┤
GPIO17 ──────────────────── [Start] ─────────────────┤
GPIO18 ──────────────────── [Select] ────────────────┤
GND    ─────────────────────────────────────────────┘

GPIO8  ── 개방: 1P / GND에 연결: 2P (부팅 시 선택)
USB    ── Raspberry Pi USB 포트 (입력 전달)
```

조이스틱은 4방향 스위치형 기준이며 각 스위치의 NO를 GPIO에, COM을 GND에 연결합니다. 아날로그 VRx/VRy 조이스틱용 배선은 아닙니다.

각 스위치의 **한쪽 다리를 GPIO, 반대쪽 다리를 GND** 에 뭅니다. 펌웨어가 내부 풀업을 켜므로 **외부 저항은 필요 없습니다.** 눌리면 LOW 입니다.

| 논리 버튼 | GPIO | 물리 부품 |
| --- | --- | --- |
| `up` | **GPIO4** | 조이스틱 위 |
| `down` | **GPIO5** | 조이스틱 아래 |
| `left` | **GPIO6** | 조이스틱 왼쪽 |
| `right` | **GPIO7** | 조이스틱 오른쪽 |
| `punch` | **GPIO15** | A 버튼 |
| `kick` | **GPIO16** | B 버튼 |
| `start` | **GPIO17** | Start 버튼 |
| `select` | **GPIO18** | Select 버튼 |
| 1P/2P 구분 | **GPIO8** | 점퍼 — 개방=1P, GND=2P |
| 공통 | **GND** | 모든 스위치의 COM을 한 줄로 묶어 연결 |

`down` 은 아직 게임에서 쓰지 않지만 배선은 미리 넣습니다. 나중에 가드·앉기를 붙일 때 케이스를 다시 타공하지 않기 위해서입니다.

**GPIO8 점퍼** 덕분에 두 대에 **완전히 같은 펌웨어**를 굽습니다. 보드가 섞여도 점퍼만 확인하면 되고 펌웨어를 다시 구울 필요가 없습니다.

### 이 핀들은 쓰지 마세요

| 핀 | 이유 |
| --- | --- |
| `GPIO19`, `GPIO20` | 네이티브 USB D-/D+. **HID가 이 위에서 동작하므로 절대 사용 금지** |
| `GPIO0`, `GPIO3`, `GPIO45`, `GPIO46` | 스트래핑 핀. 부팅 시 눌려 있으면 부팅 모드가 바뀝니다 |
| `GPIO26`~`GPIO32` | SPI 플래시 |
| `GPIO33`~`GPIO37` | 옥타 PSRAM 탑재 모듈(N8R8/N16R8)에서 사용 |
| `GPIO43`, `GPIO44` | UART0. 시리얼 모니터가 막힙니다 |

배선이 30cm를 넘으면 각 스위치 양단에 100nF 세라믹 커패시터를 병렬로 붙여 노이즈를 줄입니다(선택).

### 펌웨어 굽기

1. 아두이노 IDE에 ESP32 보드 패키지를 설치하고 `firmware/fami_pad/fami_pad.ino` 를 엽니다.
2. **Tools** 메뉴를 아래처럼 맞춥니다.

   | 항목 | 값 |
   | --- | --- |
   | Board | ESP32S3 Dev Module |
   | USB Mode | **USB-OTG (TinyUSB)** ← 반드시 변경 |
   | USB CDC On Boot | Disabled |

   `USB Mode` 가 기본값이면 HID 장치로 뜨지 않습니다. 증상은 "버튼을 눌러도 아무 반응이 없다" 로 나타납니다.

3. **UART 포트**에 케이블을 꽂고 업로드합니다.
4. 업로드가 끝나면 케이블을 **`USB` 표기(네이티브) 포트**로 옮겨 파이에 연결합니다. ESP32-S3-DevKitC-1에는 USB 포트가 두 개이며 HID는 네이티브 쪽에서만 동작합니다.
5. 두 번째 보드는 **GPIO8을 GND에 물린 상태**로 같은 펌웨어를 굽습니다. `lsusb` 에 `FAMI FIGHTERS PAD 1P` / `2P` 로 구분되어 나타납니다.

펌웨어는 5ms 디바운스로 채터링을 거르고, `delay()` 없이 계속 폴링합니다. 폴링 주기가 곧 입력 지연이기 때문입니다. 한 플레이어가 동시에 누르는 키는 최대 4개라 HID 표준 6키 롤오버 안에 들어가고, 두 대가 독립된 HID 장치라 서로 간섭하지 않습니다.

### 배선 점검

게임을 켜기 전에 배선부터 확인합니다.

```bash
python3 input_adapter.py --test
```

두 패드의 버튼 8개 상태, 각 버튼의 GPIO 번호, 누적 입력 횟수, **노이즈(채터링) 의심 횟수**가 함께 표시됩니다.

| 증상 | 확인할 점 |
| --- | --- |
| 아무 버튼도 반응 없음 | `USB Mode` 가 USB-OTG인지, 네이티브 USB 포트에 꽂았는지 |
| 특정 버튼만 반응 없음 | 해당 GPIO 배선과 GND 공통선 |
| 1P/2P가 뒤바뀜 | GPIO8 점퍼 |
| 한 번 눌렀는데 여러 번 들어감 | 노이즈 수치 확인. 스위치 교체 또는 커패시터 추가 |

### 다른 통신 방식으로 바꾸려면

`input_adapter.py` 의 `KeyboardAdapter` 자리에 `poll()` 이 `Pad` 두 개를 돌려주는 클래스를 끼우면 됩니다. 게임 코드는 건드릴 필요가 없습니다. BLE HID나 UDP로 가더라도 이 경계만 지키면 됩니다.

## 소프트웨어 구조

```text
fami-prototype/
├── launcher.py           # 게임 선택, 실행, 복귀, 종료 확인
├── games.json            # 게임 등록 목록
├── console_ui.py         # 800×480 공통 화면과 입력
├── pong.py               # 2인용 패들 듀얼
├── main.py               # 화면 상태, 게임 루프, 전투 판정, 렌더링, 화면 문구
├── input_adapter.py      # 논리 버튼 8개, 키보드/HID 어댑터, 배선 점검 화면
├── fonts.py              # 한글 폰트 탐색 (실제 렌더 결과까지 확인)
├── assets/
│   └── fonts/            # 직접 넣은 폰트를 최우선으로 사용 (선택, 비워도 됨)
├── firmware/
│   └── fami_pad/
│       └── fami_pad.ino  # ESP32-S3 조작기 펌웨어 (1P/2P 공용)
├── requirements.txt      # Python 의존성
├── .gitignore
└── README.md             # 이 문서
```

```text
물리 장치                 input_adapter.py            main.py
─────────                 ────────────────            ───────
키보드          ─┐
                 ├─ KeyboardAdapter.poll() ─ Pad×2 ─ Game.handle_pads()
ESP32 USB HID   ─┘        (논리 버튼 8개)             Game.update()
                                                     Fighter.update()
```

### `main.py`

- `Game` — 화면 전환(`title` / `fight` / `match_over`), 라운드·매치 흐름
- `handle_pads()` — 논리 버튼을 씬 전환과 캐릭터 행동으로 옮김. `update()` 보다 먼저 돌아 공격이 눌린 프레임에 바로 시작됨
- `Fighter` — 이동·점프·공격·체력·피격 상태. 위치는 **실수 좌표**로 들고 `rect` 는 렌더링·판정용으로 파생
- `separate_fighters()` / `resolve_hits()` — 몸통 밀어내기와 양쪽 판정 동시 확정
- `AttackSpec` / `ATTACKS` — 공격 타이밍·판정·피해를 모은 표
- `STRINGS_KO` / `STRINGS_EN` — 화면 문구. 폰트 가용성에 따라 통째로 선택

### `input_adapter.py`

- `Pad` — 컨트롤러 한 대의 상태. `held`(누르고 있음)와 `pressed`(이번 프레임에 새로 눌림)를 구분
- `KeyboardAdapter` — 키보드 상태를 논리 버튼으로 변환. USB HID 조작기도 같은 경로
- `pressed` 는 `KEYDOWN` 이벤트가 아니라 **프레임 간 상태 차이**로 계산합니다. 이벤트 전달 방식에 판정이 좌우되지 않고, 어떤 어댑터를 끼워도 엣지 판정 규칙이 한 곳에만 존재합니다
- `ESP32_PINS` — 배선표 사본. 진단 화면이 버튼별 GPIO를 표시하는 데 씁니다

### `fonts.py`

- `find_korean_font()` — 사용 가능한 한글 폰트 경로, 없으면 `None`
- `_draws_hangul()` — 폰트 이름을 믿지 않고 "한글"을 렌더해 같은 폰트의 `.notdef` 와 픽셀 비교

3. 60초 라운드, 체력 판정, 2선승제가 오류 없이 완료된다.
4. 화면과 조작 안내만으로 처음 사용하는 사람이 대전을 시작할 수 있다.
5. 전원·디스플레이·입력 장치를 포함한 상태로 시연할 수 있다.

## 문제 해결

| 증상 | 확인할 점 |
| --- | --- |
| `No module named pygame` | 가상환경을 활성화한 뒤 `python3 -m pip install -r requirements.txt` 재실행 |
| 창이 열리지 않음 | Raspberry Pi OS Desktop에서 실행 중인지, HDMI 출력이 정상인지 확인 |
| 키가 먹지 않음 | Pygame 창을 한 번 클릭해 포커스를 준 뒤 다시 입력 |
| 조작기가 반응하지 않음 | `python3 input_adapter.py --test` 로 배선부터 확인. [배선 점검](#배선-점검) 참고 |
| 게임을 끌 방법이 없음 | `Start` + `Select` 동시 입력. 키보드는 `Enter` + `Esc` |
| 문구가 영어로 나옴 | 한글 폰트가 없는 것. `sudo apt install -y fonts-nanum` 후 재실행 |
| 글자가 빈 네모로 나옴 | 정상적으로는 발생하지 않음. `assets/fonts/` 에 넣은 폰트가 한글을 포함하지 않는 경우 |
| 화면이 작거나 잘림 | `python3 launcher.py --fullscreen` 실행. 가장자리가 잘리면 `--margin 5` 추가 |
| DisplayPort 모니터에 신호 없음 | 단순 케이블이 아닌 능동형 HDMI → DP 어댑터인지 확인 |

**입력 계층 분리**

- `input_adapter.py` 신규. 논리 버튼 8개(`left` `right` `up` `down` `punch` `kick` `start` `select`)
- `pressed` 를 `KEYDOWN` 이벤트가 아닌 프레임 간 상태 차이로 계산
- `main.py` 에서 키 상수와 `handle_event` 제거, `handle_pads` 로 교체

**ESP32 조작기**

- 버튼 수를 게임의 논리 명령에서 역산해 **8개**로 확정 (페미컴 원본 패드와 동일)
- 배선 확정: GPIO 4/5/6/7(십자) · 15/16(A/B) · 17/18(Start/Select) · 8(1P/2P 점퍼)
- `firmware/fami_pad/fami_pad.ino` 신규. 두 대 공용, USB HID 키보드, 5ms 디바운스
- `input_adapter.py --test` 배선 점검 화면 (버튼별 GPIO·입력 횟수·노이즈 횟수)

**한글화**

- `pygame.font.Font(None, ...)` 기본 폰트에 **한글 글리프가 없어** 일시정지·매치 종료 문구가 빈 네모로 나오던 문제 발견 및 수정
- `fonts.py` 신규. 렌더 결과까지 확인하는 폰트 탐색, 실패 시 영문 자동 폴백
- 한글 폰트의 큰 행 높이에 맞춰 HUD(막대 82→92px)와 타이틀 6줄 재배치

**검증** — 무작위 입력 스모크 테스트 약 36,000프레임(가상 600초) 기준 예외·경계 이탈·바닥 관통·체력 범위 위반 0건, 지상 몸통 겹침 0프레임. 펌웨어와 `input_adapter.py` 의 키 매핑 8버튼 × 2P + 핀 번호를 기계적으로 대조해 불일치 0건.

## 개발 규칙

- 새 Python 패키지는 `requirements.txt` 에 버전 범위와 함께 기록합니다.
- 이미지/사운드/폰트 등 큰 파일은 `assets/` 아래에 종류별로 저장합니다.
- 화면에 새 문구를 넣을 때는 `main.py` 의 `STRINGS_KO` 와 `STRINGS_EN` **양쪽**에 추가합니다. 한글 폰트가 없는 환경에서도 글자가 깨지지 않게 하기 위해서입니다.
- 공격 수치를 바꿀 때는 `ATTACKS` 표만 고칩니다. 이득 프레임이 발동 프레임을 넘지 않는지 확인하세요.
- 하드웨어 핀 배정, ESP32 펌웨어 버전, 통신 프로토콜은 확정 즉시 이 문서에 표로 기록합니다.
- 펌웨어의 키 매핑과 `input_adapter.py` 의 `KEYBOARD_LAYOUTS` 는 항상 같아야 합니다. 한쪽만 고치지 마세요.
- Raspberry Pi에서 확인한 명령은 macOS 개발 환경과 구분해 문서화합니다.

### 조작기 시스템 키 업데이트

1P START/SELECT는 Enter/Esc, 2P는 F2/F3입니다. 다른 조작기의 버튼이 종료 조합으로 섞이지 않도록 구분합니다. **기존 조작기는 최신 `firmware/fami_pad/fami_pad.ino`를 다시 업로드해야 합니다.** GPIO 배선은 같습니다. 배선 점검 화면도 전체 화면에 맞춰 축소되며 같은 패드의 START + SELECT로 종료할 수 있습니다.
